# 0.14.4 验证报告

桌面 0.14.4，Chrome 扩展继续使用 0.9.3。

## 本次修改

- API 默认配置与每个命名预设可分别保存系统代理、直连、Clash 当前路由、Clash 指定节点或自定义代理。
- 手动翻译、网页自动翻译、图片自动翻译、并行图像处理、连接测试及模型列表统一使用路由连接池。
- 系统代理和直连独立于 Clash。指定节点复用已安装内核，以独立子进程和独立代理端口运行，配置仅通过标准输入传递；不修改订阅、主内核配置或当前节点。
- 使用 Windows Job Object 在父进程退出时结束独立通道。配置不进入文件、命令行、日志或安装包。
- 改变线路会重建翻译服务连接，译文缓存身份保持不变；预设切换丢弃迟到的模型列表、节点列表和连接测试结果。
- 未检测到 Clash Verge 时提供[官方 GitHub 下载](https://github.com/clash-verge-rev/clash-verge-rev/releases/latest)入口。

## 本机真实 Clash 验证

使用已安装的 Clash Verge 2.5.8 / Mihomo 1.19.32，通过本地命名管道读取可用节点；未读取翻译 API Key。从两个不同节点创建独立通道，并发 HTTPS 请求返回 200。

- 两个独立端口均正常。
- 首次启动分别约 162 ms、106 ms。
- HTTPS 响应头分别约 185 ms、433 ms；是该次网络测量，不代表 API 翻译耗时。
- 两个通道合计约 66 MiB 工作内存。
- 比较测试前后的主内核节点选择及配置文件：均一致。
- 结束测试后两个自建通道均退出，原 Clash 进程保留。

## 限制与参考

直连关闭应用层代理，系统 TUN / VPN 仍决定底层路由。独立节点使用 Clash 当前本地订阅缓存，缓存缺失或节点被移除时提示重新读取或更新订阅。没有捆绑 Mihomo，也没有新增语言模型、Chrome 权限或翻译云请求。
