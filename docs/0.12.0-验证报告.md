# 0.12.0 网页程序识别与稳定性

## 找到的原因

1. **批次交接竞态**：旧实现将“完成”消息发给 Chrome 后才清理活动请求。前端立即发送下一批时，后台仍认定有请求执行，拒绝了后续批次。新回归测试在旧实现中失败；修复后通过。
2. **识别与 API 队列共用工作槽**：新页面的语言判断可能等待其他标签的 API 请求完成。现在程序判断和判断缓存查询在入队前进行，可提前告知页面识别结果。
3. **恢复条件过窄**：只在首次判断前重试临时拒绝，部分异常还永久锁住自动任务。现在区分配置错误与临时故障，有限重试并保留已完成段落。
4. **少量中文误触发混排判断**：旧规则只要出现四个汉字就跳过整页。现在检查正文与语言证据，中文品牌或名字不等同于可读中文段落。

## 固定程序识别

- 删除 NTextCat 依赖、Core14 权重、模型和混合模式入口。旧配置迁移为程序规则。
- 根据可读正文、Unicode 脚本、常用词和整页统计判断；代码、表单、可编辑区域、数字及元数据继续过滤。
- 中文及真正包含中文正文的双语页面保留；少量中文标题、名称和导航不否决外语正文。
- 少量日语引用不会覆盖英文正文的主语言判断。
- 站点验证和加载页等待内容变化，不将加载文字交给翻译服务。
- 网页译文缓存与 API 协议、预设保持兼容；不加载网页语言模型。

7 个可访问网页的结果与人工核对的语言一致。Native 程序判断每页重复 100 次，中位数约 0.14–0.33 ms，P95 约 0.16–0.52 ms；首个冷调用约 18 ms。数据只说明这些样例，不作为全部网页的总体准确率。

另在 StarVPN、两张 Hugging Face 模型卡和 MDN 英文页面运行实际前端模块，验证多批次流式显示、最终文字稳定、原文切换和译文恢复，4 页均通过；首批候选发出约 18–26 ms。流式响应由本地测试夹具控制，不代表云 API 延迟或翻译质量。

MoreVPN KB 与 OurVPNs 在匿名测试浏览器遇到站点验证，未绕过验证，未计入成功正文样例。

## 回归与运行检查

核心测试 719 项、Windows 集成测试 600 项、Chrome 扩展测试 271 项，共 1,590 项通过，无失败或跳过。

新增检查包含批次交接、全部 API 工作槽占用时的提前识别、临时失败恢复、后续批次繁忙时保留完成段落、密钥更新后的恢复、验证页等待与正文出现后的识别。

自包含发布包运行检查通过：实际 WPF 设置页、服务商预设、本地图片检测、字体和三个原位嵌字区域正常；网页语言模型文件与 DLL 不存在。检查未读取用户 API Key，未截图桌面，未模拟用户输入。
