# 0.12.2 日期撤回与表单说明漏扫描

## 定位结果

1. 完整英文日期被元数据规则跳过，缩写月份却会进入模型。事实校验只识别完整月份名称，因此 Sep 1 的数字被视为普通数量；合法的 9月1日译法不通过校验。
2. 校验检查同批次是否挪走数字。误判日期后，包含“一个”的正常中文介绍也可能被错误视为数字接收者，连带撤回。使用用户指出的介绍与 Sep 1 组成回归用例，旧实现同时拒绝日期和介绍；修复后接受合法译文，错误日期仍拒绝。
3. Qwen 页面将 Inference Providers 区域放在 form 中。旧扫描器跳过整个 form，因此标题、状态说明和按钮均缺失。

## 实现

- 扩展和正式后台支持本地日历标签转换：完整及缩写英文月份、带年份或不带年份日期、常见 ago 等相对时间。相对时间保留数字；不依据当前时间猜测年份或时区。
- 日期不进入模型请求。独立 TIME 分组保留原文与完成译文，更新时间不撤回邻近介绍。
- 事实校验识别缩写月份及英文月份后的点，保持合法的日历格式转换，同时继续拒绝日期、数量、时间或货币事实改变。
- 扫描表单中的静态可见文字；INPUT、TEXTAREA、SELECT、OPTION、可编辑内容、隐藏区域和代码继续排除。表单文字不作为页面正文的语言判断依据。
- 补充批次计数诊断，仅记录数量与失败标记，不记录原文、API Key 或网址。

## 真实页面验证

独立匿名 Chrome for Testing，使用正式前端扫描、动效、日期转换与缓存模块。翻译流式响应由本地测试夹具提供，未读取用户密钥、未调用云模型。
