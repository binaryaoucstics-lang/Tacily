# 0.12.1 同一文档分页自动翻译

## 原因与修复

- Spaces 分页使用前端路由，文档不会重载。手动整页或选区翻译模式原先留在文档上，下一页无法进入自动扫描。本次将手动操作范围限制到当前路由。
- 原先替换正在翻译的内容时会发送不含请求 ID 的取消消息；正式后台将这种取消解释为暂停整个自动会话。现在内容替换按请求 ID 取消，显式暂停仍由独立控制消息负责。
- 新增 Chrome Navigation API、浏览器地址更新与前进后退通知，并在 DOM 更新时检查当前路由；不修改网站的 history 方法，没有新增轮询或权限。
- 保留完成段落和原文判断缓存。重复通知合并；普通锚点不重置任务。自动模式关闭及显式暂停继续生效。

## 真实网页测试

使用独立匿名 Chrome for Testing，会话与用户浏览器隔离。在 Hugging Face Spaces 运行正式内容扫描、动效、浮窗与路由模块。

| 操作 | 结果 |
|---|---|
| 本页使用整页翻译后，从 p=2 到 p=3 | 24 个非空应用介绍全部自动显示译文 |
| 继续到 p=4 | 23 个非空应用介绍全部自动显示译文 |
| 后退到 p=3、p=2 | 均恢复缓存，新增翻译请求为 0 |
| 前进到 p=3、p=4 | 均恢复缓存，新增翻译请求为 0 |
| p=5 输出前缀时后退到 p=4，延迟返回 p=5 的结果 | 按 ID 取消旧请求；p=4 的 23 个介绍仍与首次完成结果一致 |

7 个操作场景通过。检查实际卡片链接及文本，等待加载完毕，避免将空的加载列表计入成功。源文候选没有混入已输出的译文。两次完整测试均通过；最后一次新分页首批候选在点击后约 0.42–0.47 秒发出，包含网站加载时间，不代表云翻译响应速度。

正式 .NET 程序规则另外判断 p=3、p=4、p=5 的真实原文样本，三个页面均判为需要翻译。每页重复 100 次，判断中位数约 0.14 毫秒；首个冷调用约 17 毫秒。没有加载语言模型。

前端流式响应由本地夹具生成，并模拟正式后台的取消与暂停语义，未调用用户 API。这里验证识别、生命周期、渲染与缓存，不评估云模型翻译质量。

## 回归及发布检查

核心测试 719 项、Windows 集成测试 600 项、扩展测试 278 项，共 1,597 项通过，无失败或跳过。

两个新增回归用例在原实现中均失败：手动模式翻页后不退出、内容替换取消缺少请求 ID。修复后通过；其他新增检查包含重复路由通知、普通锚点、查询参数和 hash 路由、手动选区的过期响应及关闭自动模式后的分页。

自包含发布包另执行运行检查，确认实际 WPF 设置页、API 协议与预设、图片文字检测、字体及原位嵌字资源正常。没有新增模型、依赖或 Chrome 权限；默认并发保持 10。源码导出执行隐私扫描，打包文件检查不包含用户密钥、设置、日志和语言模型权重。
